Personas Context Library

Ongoing initiative Freddie Mac · Multifamily Product Design

Turning our team's personas into an AI-native context library for agentic prototyping.

Problem

Our team's personas were static image files made by a consultant in 2020, and nobody had touched them in five years. Each one had a stock photo, a name, a job title and a short story.

Our team now designs with AI, and these files couldn't be used there. AI doesn't know who our users are unless we tell it.

The idea: personas as context

I was asked to update the personas. I suggested we treat them as context instead, which meant two jobs: refresh the content and rebuild the format.

Each persona is now a Markdown file in a Bitbucket repo, as part of our team's context library. The files are also added to an internal SharePoint to supplement the Knowledge Graph, and linked to a Copilot Notebook so people who aren't set up in an IDE can query them.

Because the files are plain text, anyone can edit them. Version control means they won't go stale again.

Designing the schema with the team

I ran a FigJam session with the team around one question: what information would help you in a persona?

How it's organized

myOptigo is built around 4 business blocks: Production & Sales, Underwriting, Capital Markets, and Operations. The library follows the same structure, with one folder per block, and some blocks split further by division. Each persona is one Markdown file.

Research and validation

Every persona starts from the same prompt, run through Microsoft Copilot with access to internal docs. Copilot turns those reports into our standard schema, so each first draft has the same shape.
